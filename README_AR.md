# مجموعة التقويم التربوي — حزمة الموقع

واجهة عربية RTL متجاوبة لمكتبة الاختبارات ونماذج الإجابة، مع لوحة إدارة خاصة لرفع الملفات وتعديل بياناتها ونشرها أو حذفها.

## ما الموجود في الحزمة؟
- `index.html`: واجهة المكتبة العامة والبحث والتصفية حسب الصف ونوع المورد.
- `admin.html`: تسجيل دخول الإدارة وإدارة الموارد.
- `styles.css`: الهوية البصرية المتجاوبة.
- `app.js`: عرض المكتبة العامة وتنزيل الموارد.
- `config.js`: مكان إعداد عنوان مشروع Supabase ومفتاحه العام.
- `supabase-schema.sql`: الجداول وسياسات الصلاحيات وحاوية التخزين.
- `seed-files/`: الملفات المرفقة حاليًا لاستخدامها عند الإطلاق الأول.

## تنبيه مهم
هذه الحزمة جاهزة للربط والنشر، لكنها **لن توفر لوحة رفع سحابية دائمة قبل إعداد Supabase**. عند فتحها محليًا، تعرض المكتبة الملفات الأولية المضمنة وتسمح بتنزيلها؛ تسجيل الدخول والرفع السحابي يتطلبان إكمال الإعداد أدناه. لم يتم نشر الموقع على الإنترنت تلقائيًا لأن ذلك يحتاج حساب استضافة ومشروع قاعدة بيانات يخصّانك.

## الملفات الأولية الموجودة
1. اختبار تقنية المعلومات — الصف السابع، الفصل الأول 2026/2027.
2. اختبار تقنية المعلومات — الصف الثامن، الفصل الأول 2026/2027.
3. اختبار تقنية المعلومات — الصف التاسع، الفصل الأول 2026/2027.
4. نموذج إجابة الاختبار — الصف السابع.
5. نموذج إجابة الاختبار — الصف الثامن.
6. ملف «معلومات السابع» كموارد مساندة.

لا يوجد في الملفات التي أُدرجت في الحزمة نموذج إجابة للصف التاسع؛ لذلك لم أضف موردًا غير متوفر.

## خطوات تشغيل الموقع على الإنترنت

### 1. إنشاء مشروع Supabase
1. افتح https://supabase.com وأنشئ مشروعًا جديدًا.
2. من لوحة المشروع، افتح **SQL Editor**.
3. انسخ محتوى `supabase-schema.sql` كاملًا وشغّله مرة واحدة.
4. من **Project Settings → API** انسخ **Project URL** و**anon/public key** فقط.
5. افتح `config.js` واستبدل `YOUR_SUPABASE_PROJECT_URL` و`YOUR_SUPABASE_ANON_KEY` بالقيمتين.
6. لا تضع مفتاح `service_role` في الموقع مطلقًا.

### 2. إنشاء حساب الإدارة
1. من Supabase افتح **Authentication → Users → Add user** وأنشئ حسابًا بالبريد وكلمة مرور قوية.
2. انسخ معرّف المستخدم `UUID` من جدول المستخدمين.
3. في SQL Editor نفّذ الأمر التالي بعد استبدال `USER_UUID` بالمعرّف الحقيقي:

```sql
insert into public.admin_profiles (user_id)
values ('USER_UUID');
```

هذا الجدول هو قائمة السماح للمسؤولين؛ إنشاء حساب دخول وحده لا يمنح صلاحية الإدارة.

### 3. نشر الموقع
**خيار بسيط: Netlify أو Vercel**
1. ارفع مجلد المشروع إلى مستودع GitHub خاص بك أو اربطه بخدمة الاستضافة.
2. انشر محتويات المجلد `taqweem-site` بوصفها موقعًا ثابتًا؛ ملف البداية هو `index.html`.
3. اختبر الصفحة العامة ثم افتح `/admin.html` وسجّل الدخول بحساب الإدارة.
4. ارفع الملفات الأولية من لوحة الإدارة لتصبح محفوظة في التخزين السحابي بدل الروابط المحلية.

يمكن أيضًا نشر المجلد عبر GitHub Pages، لكن أي تعديل على ملفات الموقع أو `config.js` يتطلب تحديث المستودع وإعادة النشر. تجنّب تضمين أي مفاتيح سرية في المستودع.

## رفع الملفات الأولية إلى المكتبة السحابية
بعد النشر وإعداد حساب الإدارة:
1. افتح `admin.html` وسجّل الدخول.
2. أضف كل ملف من `seed-files/` من خلال نموذج «إضافة مورد جديد».
3. اختر الصف ونوع المورد، وأضف العنوان والوصف، ثم اضغط «حفظ ونشر المورد».
4. لا تعتمد المكتبة على أسماء الملفات فقط؛ احرص على اختيار التصنيف الصحيح قبل الحفظ.

## الأمان والخصوصية
- الملفات محفوظة في حاوية تخزين خاصة، وروابط التنزيل مؤقتة.
- يستطيع الزوار قراءة بيانات الموارد المنشورة فقط.
- عمليات الرفع والتعديل والحذف محصورة في الحسابات المسجلة داخل `admin_profiles`.
- لا ترفع بيانات الطلبة أو أي معلومات شخصية حساسة ضمن الملفات العامة.
- استخدم كلمة مرور قوية، وفعّل وسائل الحماية المتاحة في حساب الاستضافة وقاعدة البيانات.
